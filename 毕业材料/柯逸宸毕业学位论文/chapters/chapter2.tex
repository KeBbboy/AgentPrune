\section{多智能体系统}

第\ref{chap:intro}章已从问题提出角度说明多智能体系统的研究动机。本节进一步从系统实现视角归纳现有大语言模型多智能体系统的主要形态。总体来看，相关工作可以分为角色协作型、工具增强型和通信组织型三类；三类方法分别强调任务如何分工、外部能力如何接入以及信息如何在智能体之间流动。

角色协作型系统通过提示词、角色职责和对话协议把复杂任务拆解为多个协作环节。多智能体辩论方法利用多个模型或多个角色之间的交叉质询提升答案可靠性\cite{ref31,ref34}；ChatDev和MetaGPT等框架则将软件开发或复杂任务执行组织为阶段化流程，使不同角色在较明确的任务边界内协同工作\cite{ref9,ref35}。这类方法的优势在于能够把单模型难以完成的任务拆解为更稳定的协作过程，但其通信方式往往依赖预设流程和较充分的信息共享，容易在多轮交互中累积重复上下文。

工具增强型系统关注智能体如何调用外部模型、API、搜索引擎或代码执行器。MRKL、HuggingGPT和Gorilla等工作从工具路由、模型调度和API使用角度增强大语言模型的执行能力\cite{ref75,ref76,ref77}；API-Bank、WebGPT和ReWOO等研究进一步表明，工具调用会把检索证据、函数返回和中间观察写入上下文\cite{ref78,ref81,ref82}。在多智能体场景中，这些外部观察不仅影响当前智能体，还可能被传递给后续智能体，从而使通信成本和工具成本耦合起来。

通信组织型系统则关注智能体之间的信息流如何被组织。可编程对话框架、智能体社会模拟和工作流编排方法为多智能体交互提供了不同组织形式\cite{ref36,ref37,ref79}；外部记忆和并行函数调用等机制也使跨轮状态管理和工具观察传播更加复杂\cite{ref83,ref84}。因此，多智能体系统的通信效率不仅取决于是否存在多个角色，还取决于消息内容是否精炼、通信路径是否必要以及工具观察是否被重复传播。基于这一点，后续两节分别从消息内容层面的语义冗余问题和通信路径层面的通信冗余问题展开讨论。


\section{语义冗余问题}

\subsection{定义和分类}

在既定通信拓扑下，从语义维度对智能体传递的上下文消息进行压缩，是降低大语言模型推理成本和上下文占用的另一项重要手段。与拓扑优化关注“哪些智能体之间需要通信”不同，语义冗余问题更关注“沿通信链路传递什么内容”。在多智能体系统中，语义冗余问题通常指智能体之间传递的自然语言消息中包含较多重复推理、弱相关背景、低贡献解释或过长历史记忆，使下游智能体需要在更长上下文中寻找有效信息。

结合多智能体通信过程，语义冗余问题可分为三类。第一类是\textbf{角色不匹配冗余}，即发送方完整推理并不完全符合接收方智能体的角色职责，导致下游节点接收较多与自身任务无关的信息。第二类是\textbf{多前驱重复冗余}，即多个上游智能体围绕同一事实、同一公式或同一候选答案给出相似表述，增加上下文长度但信息增量有限。第三类是\textbf{跨轮历史冗余}，即多轮协作中历史消息逐轮累积，使后续智能体难以从冗长上下文中定位当前共识、关键分歧和有效证据。

\subsection{通用应对策略}

硬提示词压缩旨在通过对原始文本进行修改，生成可读且更为精简的自然语言序列。与软提示压缩将上下文映射为不可读的连续向量不同，硬提示词压缩保留了自然语言形式，因此更便于人工检查、跨模型迁移以及在多智能体通信场景中复用。与之相关的软提示和上下文状态压缩方法通常把历史信息压缩为特殊向量、摘要状态或可复用记忆，从而减少后续模型调用中的显式文本长度\cite{ref86,ref87}。根据压缩机制的不同，硬提示词压缩相关研究可划分为以下两个方向\cite{ref54}：

\par\indent \textbf{基于过滤的压缩方法：}
此类方法通过评估词元、短语或句子的重要性，剔除冗余和低信息量的部分，并在保持原文顺序的基础上生成压缩后的上下文。早期代表性工作SelectiveContext\cite{ref55}利用较小规模的因果语言模型计算词元的自信息或困惑度，将低自信息内容视为更容易由上下文预测、因而冗余度更高的部分，再按照词元、短语或句子粒度进行过滤。该方法无需额外训练，能够应用于黑盒LLM，但由于其重要性评估主要依赖语言统计特征，可能误删对特定任务有用但语言上并不突出的信息。LLMLingua\cite{ref56}进一步提出粗到细的压缩框架，首先通过预算控制器在指令、示例和问题等不同提示词组成部分之间分配压缩率，再利用小模型估计词元困惑度或信息熵，逐步保留高信息量词元。LongLLMLingua则面向长上下文场景进一步考虑查询相关性和文档级信息筛选\cite{ref85}。相比简单过滤，上述方法考虑了提示词内部不同模块的重要性差异，并通过迭代式压缩缓解局部删除造成的上下文断裂问题，因此能够在较高压缩率下保持较好的下游任务性能。

后续的LLMLingua-2\cite{ref57}则引入了数据蒸馏机制，将压缩任务从基于困惑度的无监督筛选转化为词元级二分类任务。具体而言，该方法先利用强模型生成抽取式压缩结果，再通过自动对齐为原始文本中的词元标注“保留”或“删除”标签，并训练轻量级双向编码器预测每个词元的重要性。推理时，模型按照保留概率选择满足压缩预算的词元，并保持其原始顺序。由于双向编码器能够同时利用左右上下文，LLMLingua-2在压缩速度、忠实度和跨任务泛化方面均优于单纯依赖困惑度的方法。进一步地，TACO-RL\cite{ref58}将强化学习引入过滤式压缩过程，将每个词元的保留或删除视为动作，并根据下游任务表现给予奖励。检索增强场景中的RECOMP也体现了选择性保留外部证据、减少冗余文档输入的思路\cite{ref88}。通过这种方式，压缩器能够根据具体任务目标动态调整剪枝策略，使其更倾向于保留与当前查询或任务评价指标直接相关的信息，从而弥补任务无关过滤方法在语义选择上的不足。

\par\indent \textbf{基于重写的压缩方法：}
与简单的删除词元不同，此类方法利用语言模型的生成与概括能力，主动将冗长的上下文重写为更紧凑的自然语言表达。其核心优势在于能够跨越句子边界进行信息重组，将分散在原文不同位置的关键信息合并为更短的表述，从而避免纯过滤方法可能造成的语义割裂或可读性下降。例如Nano-Capsulator框架\cite{ref59}不再从原始提示词中选择词元，而是训练一个生成式压缩模型，将长提示词封装为更短的Capsule Prompt。该模型在训练过程中同时考虑语义保持和下游任务效用：一方面要求压缩后的自然语言表示尽可能保留原始提示词的核心含义，另一方面又通过目标LLM在相关任务上的输出表现约束压缩结果，使其在压缩长度的同时仍能有效引导模型完成任务。

与过滤式方法相比，基于重写的压缩能够生成较为流畅、连贯且可读的压缩文本，尤其适合处理包含重复解释、长链式推理示例或多轮对话历史的上下文。在多智能体系统中，这类方法可用于将某一智能体的长篇推理过程、观察记录或工具调用结果重写为面向后续智能体的短摘要，从而减少跨智能体传递的词元数量。检索增强生成和多文档问答中的证据压缩同样强调在生成前压缩外部信息，以降低模型读取无关文本的负担\cite{ref91,ref92}。然而，这类方法也存在潜在风险：由于压缩过程依赖生成模型，可能出现关键信息遗漏、语义偏移甚至事实性错误。因此，在高精度任务中，重写式压缩通常需要结合任务反馈、事实一致性检测或保守的压缩率设置，以在压缩效率与语义可靠性之间取得平衡。

总体来看，通用提示词压缩方法为缓解语义冗余问题提供了基础，但其优化对象多为单模型输入，通常不显式区分发送方角色、接收方需求、多个前驱节点之间的信息重复以及跨轮历史的时序价值。同时，KV缓存压缩和流式注意力等系统优化方法主要面向推理内存与上下文窗口效率，并不判断跨智能体消息对接收方是否有用\cite{ref89,ref90}。因此，在多智能体通信场景中，语义压缩还需要结合角色关系、节点关系和历史状态进行针对性建模，以避免将对下游智能体有用的关键信息一并删除。

\section{通信边冗余}

\subsection{定义和分类}

通信冗余问题是指多智能体系统中存在低贡献、重复或成本过高的信息传递路径，使系统在没有获得相应任务收益的情况下产生额外Token消耗、工具调用开销和上下文膨胀。与语义冗余问题关注单条消息内部内容不同，通信冗余问题关注“哪些边应当存在、哪些边应当被削弱或剪除”。在工具调用场景中，该问题更为突出，因为一条通信边不仅传递发送方的自然语言推理，还可能传播搜索结果、代码执行结果和文本检查结果等高成本工具观察。

通信冗余问题可分为三类。第一类是\textbf{空间边冗余}，即同一轮内过密的智能体连接使多个下游节点读取相似或低贡献的上游输出。第二类是\textbf{时间边冗余}，即跨轮历史状态被未经筛选地传递，导致早期低贡献历史信息在多轮推理中持续占用上下文。第三类是\textbf{工具传播冗余}，即外部工具返回的长观察结果沿通信边反复传播，增加模型输入Token、工具Token和推理成本。

\subsection{通用应对策略}

针对通信冗余问题，现有方法通常将智能体视为节点、通信链路视为边，并通过图生成、图剪枝和拓扑搜索等方式减少低贡献通信路径\cite{ref38}。这类方法的共同目标是在保持协作收益的同时，使信息只沿更有贡献的边传播。早期多智能体强化学习中的通信学习方法已经验证，可学习消息通道和通信门控能够在协作任务中减少无效交互\cite{ref93,ref94,ref95}。

\par\indent \textbf{基于图生成的策略：}
图生成方法旨在根据任务条件自适应构造通信拓扑，而非完全依赖人工预设结构。
\begin{figure}[H]
  \centering
  \includegraphics[width=0.65\textwidth]{image/第一章/图1-4：图生成技术.png}
  \caption{图生成技术示意图}
  \label{fig:graph_generation}
\end{figure}

DyLAN（Dynamic LLM-Agent Network）\cite{ref39}不预先固定所有智能体之间的通信关系，而是将多智能体协作过程建模为随任务推进变化的前馈式动态网络。其核心机制包括两个阶段：首先在候选智能体集合中进行团队优化，利用Agent Importance Score评估不同智能体在当前任务上的边际贡献；随后在任务求解阶段，根据每一轮智能体输出的有效性动态选择后续参与通信的节点。DyLAN还引入早停机制，当系统已经形成足够稳定的答案或共识时提前终止多轮交互。因此，该方法主要通过减少低贡献智能体的参与次数和削减无效讨论轮次降低成本，并动态生成更贴合当前查询的通信图。注意力通信、图信息瓶颈和目标通信等方法也为稀疏化智能体交互提供了图建模基础\cite{ref96,ref97,ref98}。

CommFormer\cite{ref40}将多智能体强化学习中的智能体表示为图节点，将通信信道表示为有向边，并通过可微的图结构学习机制直接优化通信拓扑。其关键做法是对离散边选择进行连续松弛，使邻接矩阵能够参与梯度更新，同时在Transformer结构中引入关系增强注意力，以建模智能体间的依赖关系。G-Designer\cite{ref41}面向LLM多智能体系统，将每个智能体的基础模型、角色、状态、工具插件等编码为节点特征，并额外引入任务虚拟节点来表达当前查询需求，随后使用变分图自编码器生成面向特定任务的通信图。MCGD\cite{ref42}则从多智能体强化学习角度构建稀疏协调图，通过图扩散模型学习有效交互模式，体现了只显式建模关键邻居关系、避免全体智能体两两交互的思路。

\par\indent \textbf{基于图剪枝的策略：}
图剪枝方法通常从密集拓扑出发，逐步删除低贡献节点或通信边，使冗余通信图收敛为更稀疏的协作结构。

  \centering
  \includegraphics[width=0.65\textwidth]{image/第一章/图1-5：图剪枝技术.png}
  \caption{图剪枝技术示意图}
  \label{fig:graph_pruning}
\end{figure}

AgentPrune\cite{ref43}将LLM多智能体系统表示为空间-时间通信图：同一轮智能体之间的信息交换为“空间边”，跨轮历史传递为“时间边”。它为这些边学习可剪枝的图掩码，并通过系统效用评估器判断不同边对任务结果的贡献。由于外部LLM调用和任务评估通常不可微，AgentPrune使用策略梯度近似优化掩码参数，并最终执行一次性硬剪枝。AgentDropout\cite{ref44}在边剪枝基础上进一步引入节点丢弃，通过Node Dropout和Edge Dropout同时减少智能体输入、输出和后续通信边。SafeSieve\cite{ref45}采用渐进式软剪枝策略，结合LLM语义评估、角色互补性和历史任务表现修正边权，并利用聚类机制保持核心功能簇连通性。AGP（Adaptive Graph Pruning）\cite{ref46}同时进行节点级硬剪枝和边级软剪枝，使系统能够针对不同查询生成不同规模的稀疏拓扑。G-Safeguard\cite{ref47}则从安全角度构建multi-agent utterance graph，用于识别异常节点与异常话语，并通过隔离风险节点或剪断高风险外发边阻止恶意信息扩散。

\par\indent \textbf{基于拓扑搜索的策略：}
拓扑搜索通过在智能体算子和通信边构成的较大搜索空间中探索高效工作流，通常结合强化学习、蒙特卡洛树搜索或网络架构搜索算法。
\begin{figure}[H]
  \centering
  \includegraphics[width=0.65\textwidth]{image/第一章/图1-6：拓扑搜索技术.png}
  \caption{拓扑搜索技术示意图}
  \label{fig:topology_search_related}
\end{figure}

GPTSwarm\cite{ref48}将语言智能体系统统一建模为可优化图：节点可以是LLM调用、工具或数据处理函数，边表示信息流。它为候选边分配可学习的采样概率，在无环图空间中采样候选拓扑，并通过REINFORCE等策略梯度方法根据任务效用更新边概率。AgentConductor\cite{ref49}面向竞赛级代码生成任务，训练LLM为每个问题动态生成YAML格式的分层DAG拓扑，并根据编译、运行和测试反馈多轮调整拓扑。AFlow\cite{ref50}将agentic workflow表示为可执行代码中的算子组合与依赖关系，并使用蒙特卡洛树搜索探索Generate、Review、Revise、Ensemble、Test、Programmer等工作流算子。MASS（Multi-Agent System Search）\cite{ref51}交错优化prompt和topology，并对低收益模块进行影响力剪枝。MaAS（Multi-agent Architecture Search via Agentic Supernet）\cite{ref52}提出智能体超网，使每个查询只激活少量算子路径。DynaSwarm\cite{ref53}则在GPTSwarm式参数化通信图基础上引入样本级动态选择，根据输入样本路由到不同稀疏候选结构。近期自动化智能体设计和工作流编译研究进一步说明，prompt、工具调用和拓扑结构可以被统一纳入系统级搜索空间\cite{ref99,ref100,ref101}。

上述研究说明，减少无效节点、无效边和低收益工作流能够缓解多智能体系统的通信负担。但现有方法大多将通信边代价近似视为同质，或者主要依据任务效用判断边是否保留，对工具调用场景中“某条边传播了多少工具观察、造成多少下游上下文膨胀、带来了多少额外调用成本”刻画不足。尤其在搜索、代码执行和文本检查等工具增强任务中，一条边的贡献不仅取决于是否提高最终答案，还取决于它是否传播了高成本、低增益的工具信息。因此，本文第四章提出面向通信边冗余的图剪枝算法，将通信边建模为可学习概率，并把任务正确性、工具调用次数、工具返回Token和模型输出Token共同纳入边级优化目标，从而解决工具调用场景下通信边贡献异质、成本难以归因和低贡献边难以及时剪除的问题。

\section{本章小结}

本章围绕多智能体系统及其通信效率优化相关研究进行了梳理。首先，多智能体系统通过角色分工、协作推理和工具调用提升复杂任务处理能力，但也带来了通信路径膨胀和上下文累积问题。其次，语义冗余问题主要表现为角色不匹配、多前驱重复和跨轮历史冗余，现有过滤式与重写式压缩方法为减少自然语言上下文提供了基础，但仍需面向多智能体通信场景进一步适配。最后，通信冗余问题主要表现为空间边、时间边和工具传播冗余，现有图生成、图剪枝和拓扑搜索方法能够从结构层面降低系统开销，但对工具调用场景下的边级成本归因、工具观察传播和动态低贡献边识别仍不充分。上述不足共同构成了本文后续两个工作的主要动机：第三章从语义内容层面提出面向语义冗余的消息压缩框架，第四章从通信结构层面提出面向通信边冗余的图剪枝算法。
